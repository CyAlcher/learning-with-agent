## 一、GEPA 是什么（一句话人话）

**GEPA 让 LLM 当「进化算法的变异算子」，用「为什么失败」这个反馈去改进任何一段文本（提示词、代码、配置、正则、agent 架构）。**

名字拆开：Genetic（基因/进化）+ Pareto（帕累托效率）。

---

## 二、核心机制（人话）

### 传统优化为什么笨

- RL / 梯度法：只知道「这个候选得分 0.3」，不知道「**为什么**只有 0.3」。于是靠海量试错（RL 要 5000~25000 次评估）慢慢摸。
- 一个标量分数，丢掉了最有价值的「失败原因」。

### GEPA 的洞察：让 LLM 读「完整轨迹」，诊断「为什么」

评估器不返回一个数字，而是返回**诊断信息**（错误信息、日志、输出、traceback）。然后：

```
5 步循环（每一轮）：
  1. 选(Select)   —— 从帕累托前沿挑一个候选
  2. 跑(Execute)  —— 在样本 minibatch 上评估，捕获完整执行轨迹
  3. 反思(Reflect)—— 反思 LLM 读轨迹，诊断「哪里错了、为什么」
  4. 变异(Mutate) —— 反思 LLM 生成改进版候选（带着诊断结论改）
  5. 收(Accept)   —— 变好了就进池，更新帕累托前沿；没变好就丢弃
```

**关键点：反思和变异是同一次 LLM 调用完成的**——它一边读「哪里错了」，一边吐出「改成什么样」。这就是它比传统遗传算法（纯随机变异）聪明的地方。

---

## 三、帕累托前沿（最关键的概念，人话）

**不是「只留一个冠军」，是「每个子任务上的冠军都留着」。**

- 普通优化：最后给你一个「全局平均最优」的候选，把「在某个子任务上特别强」的候选平均掉了。
- GEPA：维护一张「前沿表」——`pareto_front_valset: {样本1: 最高分, 样本2: 最高分, ...}`，每个样本上得分最高的候选都保留。

举例：候选 A 在「数学题」强、候选 B 在「代码题」强，两个都留在前沿里，不互相淘汰。后面还有 **merge（合并）** 机制：把 A 和 B 的优点杂交成一个新候选。

这就是「Pareto」——不为了一个平均分牺牲局部专长。

## 四、ASI = 文本版的「梯度」

| | RL / 梯度法 | GEPA |
|---|---|---|
| 反馈信号 | 标量 reward（只知道好坏） | ASI：诊断信息（知道**为什么坏 + 怎么改**） |
| 类比 | 梯度（往哪个方向调权重） | side_info（往哪个方向改文本） |
| 效率 | 海量试错 | 100~500 次评估就够（比 RL 快 35x） |

ASI = Actionable Side Information（可行动的副作用信息）。评估器返回的 `error`、`traceback`、`stdout` 就是它——LLM 读它，等于拿到了「改哪、怎么改」的方向。

## 五、对照：我之前假设的模型 vs GEPA 实际是什么

之前我在推「决策链 → MDP → 蒸馏」时，说过「先生成垃圾，再变异，筛」。**GEPA 就是这句话的完整工业实现**：

| 我说的（口语） | GEPA 的对应 |
|---|---|
| 生成垃圾 | `seed_candidate`（一个初始候选，烂没关系） |
| 变异 | `ReflectiveMutationProposer`（反思 LLM 读 side_info 生成改进） |
| 筛 | `AcceptanceCriterion` + 帕累托前沿（好的进前沿，差的淘汰） |
| 筛给方向 | ASI（side_info 告诉变异「往哪改」） |

**关键结论：GEPA 不是 MDP，不是 RL，是「进化算法 + LLM 反思」。**

- 它**不学 policy**（不建模 state→action→reward 转移），所以不是 MDP。
- 它是**进化搜索**（evolutionary search）：候选池 + 变异 + 选择。
- 它的独特贡献：把「随机变异」升级成「LLM 诊断式变异」——这是传统遗传算法（GA）没有的。
- 我之前担心的「reward 空、result 列空」——GEPA 根本不需要预先有 reward 列：**evaluator 每次评估时现算分数 + 返回 side_info，这就是 reward + 梯度，运行时给，不用预标注。**

所以你的「决策链库缺 result」问题，GEPA 的方案是：**补一个 evaluator（评测器）就行，评测器每次现打分，不需要历史 result 列。**

## 八、坑（已踩）

1. **`max_metric_calls` 别设太小**：6 次只够评估 seed，没跑到反思变异就 budget exhausted。至少 20+。
2. **dspy 冲突**：`dspy 3.1.3 requires gepa==0.0.26`，装 0.1.4 后 `dspy.GEPA` 不兼容（不影响 `gepa.optimize_anything`）。
3. **qwen14b 在 9090，不在默认 11434**：litellm 默认连 ollama 的 11434，必须 `reflection_lm_kwargs={"api_base": "http://127.0.0.1:9090"}`。
4. **vendor gepa 0.1.4 = PyPI 最新**（已验证），但 envs/agent 原装的是 0.0.26 旧版，要 `pip install -e vendor/gepa-main` 覆盖。
