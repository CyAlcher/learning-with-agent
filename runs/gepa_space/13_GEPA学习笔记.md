# 让 LLM 自己进化出更好的 Prompt：我的 GEPA 学习笔记

> 这篇文章是我学完 GEPA（一个「让 AI 自己进化优化」的开源框架）后的笔记。它不是使用教程，而是我踩坑后悟到的一条判断标准——它改变了我写评测器的方式。如果你正在用 AI 优化 prompt、代码或配置，这条经验可能对你有用。

## 先补三个背景概念（后面会反复用到）

- **进化算法**：模仿生物进化——保留好的、随机变异、再筛选，一轮轮逼近更好的解。
- **评测器（evaluator）**：一个「给结果打分」的函数。GEPA 靠它判断「哪个候选更好」，它是整套机制的核心。
- **帕累托前沿**：不只留一个冠军，而是「在每个子任务上最强的候选」都留着，不为了平均分牺牲局部专长。

## 一句话：GEPA 是什么

**GEPA 让 LLM 当「进化算法的变异算子」——用「为什么失败」的反馈，去改进任何一段文本（prompt、代码、配置、正则、agent 架构）。**

说人话：不再靠人手动改 prompt，而是让 AI 自己改——它每轮读「上一版错在哪」，然后自己写一版更好的。

名字拆开：Genetic（遗传）+ Pareto（帕累托）。

它既不是梯度下降（不需要「损失函数可求导」），也不是强化学习（不需要提前标好「对/错」的奖励数据），而是「进化算法 + LLM 反思」：只要你能给结果打一个分，它就能优化。

## 核心机制：5 步循环

```
选(Select) → 跑(Execute) → 反思(Reflect) → 变异(Mutate) → 收(Accept)
```

每一轮：从候选池挑一个 → 在样本上跑一遍（记录完整过程）→ 反思 LLM 读过程诊断「为什么坏」→ 生成改进版 → 变好就收进池子、更新帕累托前沿。

三个值得记住的点：

1. **反思和变异是同一次 LLM 调用**——它一边读「哪里错了」，一边吐出「改成什么样」。这是它比传统遗传算法（纯随机变异）聪明的地方。
2. **帕累托前沿 = 每个子任务上的冠军都留着**——不为了一个平均分，牺牲「在某一个子任务上特别强」的候选。
3. **ASI（可行动的副作用信息）= 文本版梯度**——评测器返回的报错/堆栈/输出，就是「改哪、怎么改」的方向，相当于把「梯度」翻译成了文字。

> 补充：什么是「梯度」？简单说，梯度 = 告诉你「往哪个方向改会更好」的信号。深度学习靠算梯度来优化，GEPA 靠评测器返回的文字来当梯度。

## 我踩的最深的坑：结果指标 > 过程指标

这是我最值钱的一课，翻车两次才明白。先分清两个词：

- **过程指标**：看「产物本身长得好不好看」——比如 prompt 文本里有没有覆盖关键要素、有没有写「只输出 JSON」这类词。
- **结果指标**：看「产物拿去用，真的 work 不 work」——比如用这个 prompt 真跑一次任务，看输出能不能被下游程序正确使用。

**一句话：过程指标看「长得像不像」，结果指标看「用了行不行」。**

我第一次优化一个「从文本抽取结构化信息」的 prompt，评测器写成了「检查 prompt 文本里有没有覆盖关键要素」。结果分数从 2 分涨到 15 分，很好看。

然后我用优化出来的 prompt 真去跑任务——**抽出 0 条结果**。

为什么？我的评测器只查「prompt 好不好看」（过程指标），漏了「输出必须是一个特定的外层结构」这个命门。于是 GEPA 优化时，把那个结构示例「精简」掉了——因为打分不奖励结构、反而奖励「简洁」。分数 15 分的 prompt，实际抽不出东西。

**教训：判分测什么，模型就优化什么。** 你测「有没有这个词」，它就去堆这个词，而不是写好 prompt。要修的从来不是模型，是评测器。

## 一个真实案例

任务：优化一段「从文本抽取结构化信息」的 prompt。

- **v1（过程指标，错）**：评测器检查 prompt 文本要素。分数 2→15 很漂亮，实际抽取 0 条（漏了外层结构这个命门）。
- **v2（结果指标，对）**：评测器改成「用候选 prompt 真的跑任务，检查产出能不能被下游程序消费」。分数 0.01 → 12 满分，抽出多条结果，且全部通过「下游路由 + 执行」这一关。

关键转折在第二个问题：**「生成了 + 看起来可执行」不算终点，真正的终点是下游程序真的消费了产出。** 停在「生成」这一步，分数证明不了「下游能用」。

> 「下游」指：拿到你抽取结果、继续做下一步处理的程序或流程。你优化的是「抽取」，但抽取的成果最终要被别人用起来——那一步用不起来，前面全白费。

## 学到的 3 条核心经验

1. **判分测什么就优化什么**——评测器漏了下游契约，优化器就把契约优化掉。写评测器前，先列每个字段的「下游消费契约」表，对着表写。
2. **端到端的终点 = 下游消费的结果，不是「看起来对」**——优化 prompt 的终点是「产出被下游真正复用」，不是「JSON 结构漂亮」。
3. **框架能力上限 = 评测器质量，不是反思模型的质量**——我用的小模型反思会「跑偏」（把「抽取字段」脑补成「任务步骤」），但评测器判低分后，它下一轮就自己修正了。瓶颈从来在评测器。

> 顺带一个 GEPA 的实现细节：评测器打 0 分会触发框架的一个 bug（它内部会误以为「候选池空了」而崩溃），所以「失败」也要给一个极小正分（比如 0.01）。这个细节本身不重要，但它再次印证：**框架的边界也在评测器这一环。**

## 一句话总结

> GEPA = 把遗传算法的「随机变异」换成「LLM 读错误再改」，用评测器返回的文字当「梯度」。它解决的是「没法求导、没有预标注奖励、但能打分」的优化问题——正好是 prompt/代码/配置这类「文本参数」的处境。而它的能力上限，取决于你写的评测器能不能反映「下游真正要的结果」。
