## 一、核心判断（一句话）

**GEPA 应用层的「接地气」= 优化的对象和判分标准都从 Max 的真实历史任务里提炼，而不是跑框架自带的通用示例。**

之前 `run_circle_packing.py`（26 圆打包）不接地气：seed 是 ShinkaEvolve 的通用代码，objective 是英文的几何题，跟 Max 的供应链/决策链业务无关。学完只会「用 GEPA」，不会「用 GEPA 改善自己的现状」。

## 二、方法论：把任何历史任务变成 GEPA 应用层 3 件事

```
1. 找一条「已经存在的文本 + 可判分的任务」   ← 从历史任务里找，别造 toy
2. SEED       = 这条任务里「要优化的那段文本」的退化版（故意会出错）
3. evaluate   = 0-LLM 判分（判分标准从任务的真实要素提炼），返回 (score, side_info)
4. optimize_anything 跑 5 步循环，14B 反思变异
```

关键：**判分标准（evaluate）是最大杠杆**。判分标准从真实任务提炼 = 优化方向就是真实任务需要的方向。判分标准凭空造 = 优化方向跑偏。

## 五、验证结果：14B 怎么一步步改提示词（真实轨迹）

从 `runs/decision_chain_prompt/run_log.txt` 读到的每轮 `Proposed new text` + `[evaluate] score=`：

| 轮 | score | 14B 这一步干了什么 |
|---|---|---|
| seed | 2/16 | 一句话 `"从日报中提取决策链，输出 JSON。"`，缺 12 项 |
| Iter 1 | **2→15** | **一步补齐几乎所有要素**：角色定义 + 七字段全列 + basis_type 四选一 + 分步指令(①确定topic②提取state…) + 空值规则。只缺「只输出JSON」这一项 |
| Iter 2-5 | 15（被拒） | 反复攻「只输出JSON」：写成「仅输出JSON」「禁止任何其他文字」「不添加任何解释」——全是同义词，都没踩中判分的精确词「只输出」/「不要其他」 |
| Iter 6 | 15（被拒） | **写出真正高质量的 prompt**：markdown 加粗 + basis_type 四选一给了业务含义(铁律=公司政策/偏好=个人偏好/证据=报表合同/推断=假设) + 空数组边界 `[]`。但依然没用「只输出」这个词 |
| Iter 7 | 15（被拒） | 开始「刷语义」：把「不添加任何解释」重复 6 次（每个字段后都跟一句），质量反而下降 |

**三个待验证问题的答案**：

1. **14B 能不能从 2 分收敛到满分？** 一步到 15，但卡在最后 1 分（「只输出」精确词），最终 15/16。
2. **补要素顺序？** 第一轮一次性补齐（角色+七字段+四选一+分步+空值），说明它**理解**了「决策链抽取」需要什么，不是逐词试错；后续轮死磕最后一个要素。
3. **有没有 reward hacking？** 有迹象（Iter 7 把「不添加任何解释」重复 6 次刷语义），但**根因是判分规则太机械，不是 14B 故意作弊**——见下。

## 六、提示词逐轮原文（14B 一步步改的完整过程）

> 每轮原文 = `run_log.txt` 里 `Proposed new text for current_candidate:` 之后的完整内容。
> 标注每轮 score + 相比上一轮「改了什么」。

### seed（2/16，起点）

```
从日报中提取决策链，输出 JSON。
```

### Iter 1（2→15，被接受 = GEPA 最终 best）—— 一步补齐所有要素

```text
你是一个决策链抽取器。请从日报中提取决策链，输出严格符合以下格式的JSON，不包含任何额外内容。决策链包含以下七个字段：topic（决策事项，一句话）、state（决策前的客观现状）、decision（决策内容）、basis（决策依据，一句话）、basis_type（依据类型，必须是四选一：铁律/偏好/证据/推断）、action（决策后的行动）、result（结果，若日报中无则留空）。请按以下步骤操作：1. 确定topic；2. 提取state；3. 识别decision；4. 分析basis及对应的basis_type（必须从铁律、偏好、证据、推断中选择）；5. 记录action；6. 查找result（若日报未提及则留空）。若某字段信息缺失，请留空。
```

**改了什么**：从一句话 → 角色定义 + 七字段全列 + basis_type 四选一 + 分步指令(6步) + 空值规则。只缺「只输出JSON」这个精确词（写成了「不包含任何额外内容」）。

### Iter 2（15，被拒）—— 加了 JSON schema 硬约束

```text
你是一个决策链抽取器。请严格遵循以下指令：1. 仅输出JSON格式的结果，禁止任何其他文字或解释；2. 抽取的决策链必须包含以下七个字段：topic（决策事项，一句话）、state（决策前的客观现状）、decision（决策内容）、basis（决策依据，一句话）、basis_type（依据类型，必须从[铁律, 偏好, 证据, 推断]中严格选择）、action（决策后的行动）、result（结果，若日报中未提及则留空字符串""）；3. 按以下步骤操作：① 确定topic；② 提取state；③ 识别decision；④ 分析basis及对应的basis_type（必须从铁律、偏好、证据、推断中选择，不可遗漏）；⑤ 记录action；⑥ 查找result（若日报未提及则留空字符串""）；4. 若字段信息缺失，对应字段留空字符串""；5. JSON结构必须符合以下schema：{"type": "object", "properties": {"topic": {"type": "string"}, "state": {"type": "string"}, "decision": {"type": "string"}, "basis": {"type": "string"}, "basis_type": {"type": "string", "enum": ["铁律", "偏好", "证据", "推断"]}, "action": {"type": "string"}, "result": {"type": "string"}}, "required": ["topic", "state", "decision", "basis", "basis_type", "action", "result"]}.
```

**改了什么**：把「仅输出JSON」写得更狠（禁止任何其他文字），并追加了完整 JSON Schema（含 enum 约束 basis_type）。但判分认的是「只输出」/「不要其他」，所以仍是 15 分。

### Iter 3（15，被拒）—— 加分步语义 + 输出示例

```text
你是一个决策链抽取器。请严格遵循以下指令：1. 仅输出JSON格式，不包含任何解释、说明或其他文字；2. 抽取的决策链必须包含以下七个字段：topic（决策事项，一句话）、state（决策前的客观现状）、decision（决策内容）、basis（决策依据，一句话）、basis_type（依据类型，必须从【铁律/偏好/证据/推断】四选一）、action（决策后的行动）、result（结果，若日报中无则留空字符串""); 3. 按以下步骤操作：① 确定topic（明确决策解决的核心问题）；② 提取state（客观描述决策前的现状）；③ 识别decision（明确做出的具体决定）；④ 分析basis及对应的basis_type（必须严格从四选一中选择，若无法明确归类则选"推断"）；⑤ 记录action（决策后的具体行动）；⑥ 查找result（若日报未提及则留空字符串"")。若某字段信息缺失，请留空字符串"")。输出格式示例：[{"topic":"...","state":"...","decision":"...","basis":"...","basis_type":"...","action":"...","result":""}]
```

**改了什么**：每个分步加了「怎么判」的说明（如「若无法明确归类则选推断」），并加了 JSON 输出示例。

### Iter 4（15，被拒）—— 精简 + 强调纯 JSON 单对象

```text
你是一个决策链抽取器。请严格按照以下要求操作：1. 仅输出JSON格式内容，不添加任何解释、说明或其他文字；2. 决策链必须包含七个字段：topic（决策事项，一句话）、state（决策前的客观现状）、decision（决策内容）、basis（决策依据，一句话）、basis_type（依据类型，必须从四选一：铁律/偏好/证据/推断中选择）、action（决策后的行动）、result（结果，若日报中无则留空）；3. 若某字段信息缺失，请留空字段。请按以下步骤执行：① 确定topic；② 提取state；③ 识别decision；④ 分析basis及对应的basis_type（必须严格从铁律、偏好、证据、推断中选择）；⑤ 记录action；⑥ 查找result（若日报未提及则留空）。输出必须为纯JSON，且仅包含一个决策链对象。若无法提取完整字段，仅留空对应字段，不得省略字段。
```

**改了什么**：回到「仅输出」表述，补「输出必须为纯JSON，且仅包含一个决策链对象」。

### Iter 5（15，被拒）—— 补「错误信息」排除

```text
你是一个决策链抽取器。请严格遵循以下指令：1. 仅输出JSON格式的结果，不包含任何解释、错误信息或其他文字；2. 决策链必须包含七个字段：topic（决策事项，一句话）、state（决策前的客观现状）、decision（决策内容）、basis（决策依据，一句话）、basis_type（依据类型，必须从【铁律/偏好/证据/推断】四选一）、action（决策后的行动）、result（结果，若日报中无则留空）；3. 按步骤执行：①确定topic；②提取state；③识别decision；④分析basis及对应的basis_type（必须从四选一中选择，若无法判断则选"推断"）；⑤记录action；⑥查找result（若未提及则留空）；4. 若字段信息缺失，对应字段留空。输出示例：[{"topic":"...","state":"...","decision":"...","basis":"...","basis_type":"...","action":"...","result":""}]
```

**改了什么**：把「解释」扩成「解释、错误信息或其他文字」（想把「只输出」语义补全，仍不是精确词）。

### Iter 6（15，被拒，⚠️ 实际质量最高）—— 给出 basis_type 业务含义 + 空数组边界

```text
你是一个决策链抽取器。你的任务是从日报中严格提取结构化决策链，**仅输出JSON格式**，不包含任何解释、说明或额外文字。决策链必须包含以下七个字段：
- **topic**（决策事项，一句话）
- **state**（决策前的客观现状）
- **decision**（决策内容）
- **basis**（决策依据，一句话）
- **basis_type**（依据类型，**必须从以下四选一**：铁律/偏好/证据/推断）
- **action**（决策后的行动）
- **result**（结果，若日报中无则留空，用空字符串""表示）

请按以下步骤操作：
1. **确定topic**：明确决策解决的核心问题，用一句话概括。
2. **提取state**：描述决策前的客观现状，避免主观判断。
3. **识别decision**：提取明确的决策动作或选择。
4. **分析basis及basis_type**：
   - 若依据是明确规则（如公司政策），选**铁律**；
   - 若依据是反复纠正的倾向（如个人偏好），选**偏好**；
   - 若依据可溯源文件数据（如报表、合同），选**证据**；
   - 若依据是未验证的推断（如假设），选**推断**。
5. **记录action**：描述决策后的具体行动。
6. **查找result**：若日报未提及结果，**必须留空字符串""**，不可缺失字段。

**强制约束**：
- 输出必须为**纯JSON数组**，格式为 `[{"topic": "...", "state": "...", ...}]`，**禁止任何额外文本**。
- **basis_type必须严格四选一**，若无法确定，根据上下文推断最接近的类型。
- **空值规则**：字段信息缺失时，用空字符串""填充，不可省略字段。
- **若无决策链**，输出空数组`[]`，不可输出其他内容。
```

**改了什么**：这一版是**质量最高**的一版——给了 basis_type 四选一各自的业务含义（铁律=公司政策/偏好=个人偏好/证据=报表合同/推断=假设），加了 markdown 格式化、空数组 `[]` 边界处理。但判分认精确词，它用的「**仅输出**」仍不是「只输出」，所以 15 分被拒。

## 七、最终结果（⚠️ 待 Max 审核）

### 7.1 GEPA 判分口径的「最优」（15/16 分）

GEPA 的接受标准是「严格 > 才接受」，Iter 1 的 15 分是第一个被接受的，之后 7 轮全是 15 分「not better」被拒。
所以 **GEPA 返回的 best candidate = Iter 1 的 prompt**：

```text
你是一个决策链抽取器。请从日报中提取决策链，输出严格符合以下格式的JSON，不包含任何额外内容。决策链包含以下七个字段：topic（决策事项，一句话）、state（决策前的客观现状）、decision（决策内容）、basis（决策依据，一句话）、basis_type（依据类型，必须是四选一：铁律/偏好/证据/推断）、action（决策后的行动）、result（结果，若日报中无则留空）。请按以下步骤操作：1. 确定topic；2. 提取state；3. 识别decision；4. 分析basis及对应的basis_type（必须从铁律、偏好、证据、推断中选择）；5. 记录action；6. 查找result（若日报未提及则留空）。若某字段信息缺失，请留空。
```

### 7.2 我的判断：实际质量最高的是 Iter 6（不是 GEPA 的 best）

**GEPA 的 best（Iter 1）其实不是最好的 prompt。** 因为判分规则是「精确词匹配」，Iter 1 到 Iter 8 全部 15 分，
判分根本测不出它们之间的质量差异。真正质量最高的是 **Iter 6**（见第六节），它多给了：

- basis_type 四选一的**业务含义**（铁律=公司政策/偏好=个人偏好/证据=报表合同/推断=假设）→ 抽取时更准
- **空数组边界**（「若无决策链，输出空数组 `[]`」）→ 兜底，不抽错
- markdown 格式化 → 模型看得更清

**结论给 Max 审核**：判分规则（精确词）测不出真实质量，导致 GEPA 把「第一个 15 分」当 best，错过了「真正的 15 分」。要拿到「真最优」，得把判分规则从精确词改成语义正则 `(只|仅|禁止|不得).{0,4}(输出|其他|解释)` 再跑一轮。

## 八、验证结论

| 维度 | 结论 |
|---|---|
| 14B 能不能改提示词 | ✅ 能，且很强。一步 2→15 分，补齐角色+七字段+四选一+分步+空值 |
| 怎么一步步理解 | 第一轮「顿悟式」补齐所有要素（理解任务本质），后续轮「死磕」最后一个缺口 |
| 有没有 reward hacking | ⚠️ 有迹象（Iter 7 重复 6 次「不添加任何解释」），但根因是判分规则机械，不是 14B 故意刷 |
| **14B 的边界（最值钱的结论）** | **框架的能力上限 = evaluator 的质量，不是 14B 的质量** |

**核心发现（evaluator 是最大杠杆的实证）**：

判分规则写的是 `"只输出" in prompt or "不要其他" in prompt`（精确词匹配）。
14B 在 Iter 6 其实已经写出了**满分质量的 prompt**（业务含义齐全 + 边界处理），
但因为它用的是「仅输出」「不添加任何解释」，被判分规则卡在 15 分；
Iter 7 为了踩中判分词，开始把「不添加任何解释」机械重复 6 次——**质量反而下降**。

一句话：**判分规则测什么，14B 就优化什么。判分规则测「有没有『只输出』这个词」，14B 就去堆这个词，而不是写好 prompt。** 要修的从来不是 14B，是 evaluate 的判分规则。

这正好验证了 GEPA 官方 skill 的 gotcha：「reward hacking — 每个 backend 优化的是你打分的东西」，也验证了 leverage-first 铁律「evaluate = 最大杠杆（裁判），score 算错 → 优化方向错」。

## 九、结果指标验证（用优化出的 prompt 真抽日报，⚠️ 反转结论）

> 2026-10-16 Max 纠正：判分分数是「过程指标」，他要用优化出的 prompt **真抽日报、看抽取结果**（结果指标）。
> 脚本：`gepa_space/scripts/compare_prompts_on_real_daily.py`（4 个 prompt 抽同一段真实日报，对比）。

### 9.1 抽取结果对比（同素材：20260409.md 决策密集段）

| prompt | 判分 | 实际抽取 |
|---|---|---|
| seed 一句话 | 2/16 | 0 条链（一句话没告诉模型输出什么格式） |
| **原始 PROMPT（基线）** | 14/16 | **6 条链，basis_type 合法 6/6，五字段全填 6/6 ✅** |
| GEPA-best (Iter1) | 15/16 | **0 条链 ❌（只输出 1 条 + 结构错）** |
| Iter6 (真最优) | 15/16 | **0 条链 ❌（只输出 1 条 + 结构错）** |

### 9.2 根因（为什么判分高反而抽取废）

原始 PROMPT 有一行**外层结构示例**：
```json
{"chains": [{"topic":"...","state":"...","decision":"...","basis":"...","basis_type":"偏好","action":"...","result":"..."}]}
```
这个 `{"chains": [...]}` 是下游 `json.loads(msg).get("chains", [])` 能不能解析的**命门**。

但我的判分规则（0-LLM 检查 prompt 文本）只检查了：七字段 + basis_type 四选一 + JSON + 分步 + 空值，
**唯独漏了「输出必须是 {"chains": [...]} 外层数组」这个要素**。

于是 GEPA 优化时，14B 反思变异把这个「结构示例」**精简掉了**（判分不奖励结构、反而奖励「简洁」），
优化出的 prompt 只告诉模型「输出七个字段」，14B 就输出**单个对象** `{"topic":...}`（一条链），
而不是 `{"chains": [6条]}`。下游 `.get("chains")` 拿空 → 抽到 0 条。

### 9.3 教训（我的错，Max 一眼看穿）

**我犯了自己 leverage-first 铁律里明确警告过的「过程指标自嗨」：**
- 判分 = 检查「prompt 文本有没有覆盖要素」（过程指标）→ 分数 2→15 很好看
- 但「prompt 覆盖要素」≠「prompt 能抽出好结果」

**正确 evaluator 必须是「结果指标」**：`evaluate(candidate)` = 用 candidate 真抽一篇日报 → 检查抽取结果
（链数 > 0、结构是 {"chains":[...]}、basis_type 四选一、字段全填）→ 返回结果质量分。

一句话：**判分规则必须包含「下游能解析的完整契约」（含外层结构），不能只查「要素齐不齐」。**

### 9.4 修复方向

| 方案 | 做法 | 代价 |
|---|---|---|
| 快修 | 判分规则加「外层结构 {"chains":[...]}」要素，重跑 | 仍可能漏别的命门 |
| **对修** | evaluator 改成「真抽日报 + 检查抽取结果」，用结果质量当 score | 慢（每次 evaluate 真抽 14B），但这是唯一对的方向 |

正确落点 = 对修：把 evaluator 从「查 prompt 文本」换成「查抽取结果」，判分标准 = 链数/结构/类型/字段，
这样 GEPA 优化的是「抽取效果」，不是「prompt 好不好看」。

## 十、v2 结果指标 evaluator（Max 纠正后，成功）

### 10.1 设计：eval 里包含「协同方能用的约束」

score 三层（满分 12 = 结构3 + 落盘3 + 字段2 + 类型2 + 可执行2）：
- **① 结构化**：结果必须是 `{"chains":[...]}` 外层结构（下游 `get("chains")` 能 parse）——v1 漏的命门
- **② 落盘存在**：结果写到真实路径（不是飘在内存）——「必须输出文档的路径」
- **③ 下游消费**：字段全填 + basis_type 四选一 + **action 可拆解执行**（正放执行能直接拆步骤）

脚本：`gepa_space/scripts/optimize_decision_chain_prompt_v2.py`

### 10.2 结果（一步到位）

seed 一句话 0.01 分 → **Iter 1 reflection 读「结构错，下游解析不到」的 error，一次性补上全部下游约束 → 12 满分**。
GEPA 优化出的 best prompt 自动包含：外层结构 + 落盘路径 + action 可拆解 + basis_type 四选一 + 结构示例。

### 10.3 抽取结果对比（同素材 20260409 决策密集段）

| prompt | 判分 | 实际抽取 | action 质量 |
|---|---|---|---|
| 原始 PROMPT | 12（满分） | 6 条链 | action 一句话描述（「重构任务2输出规范并启动并行任务」，**不可拆解**） |
| v1-best（过程指标） | 15/16 | **0 条链（结构错）** | — |
| v2-best（结果指标） | 12（满分） | **6 条链** | action 可拆解执行步骤（「1.将任务4从主链剥离 2.设置独立抢占优先级标志 3.更新调度器配置文件」）✅ |

**关键差异**：原始 PROMPT 和 v2-best 都抽 6 条链，但 v2-best 的 action 是「1. 2. 3.」可拆解步骤，原始 PROMPT 的 action 是一句话描述。下游「正放执行」时，可拆解的 action 能直接执行，一句话描述拆不了。

### 10.4 结论（验证了 Max 的洞察）

**eval 里包含「协同方能用的约束」（action 可拆解 = 下游正放执行能用），评分，GEPA 就优化出真正可用的 prompt。**

| | v1（过程指标，错） | v2（结果指标，对） |
|---|---|---|
| evaluator 查什么 | prompt 文本要素 | 真抽日报 + 查结果（结构/落盘/下游消费） |
| 判分 | 2→15 卡精确词 | 0.01→12 一步满分 |
| 漏不漏命门 | 漏 {"chains":[...]} 结构 | 补上 |
| 实际抽取 | 0 条（废） | 6 条 + action 可拆解 ✅ |

**一句话**：判分规则测什么，GEPA 就优化什么。v1 测「prompt 好不好看」→ 优化出好看的废 prompt；v2 测「结果能不能被下游用」→ 优化出真正能用的 prompt。
