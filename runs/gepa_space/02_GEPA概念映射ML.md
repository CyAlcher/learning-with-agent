# GEPA 概念 → 机器学习概念映射（降低认知复杂度）

> 日期：2026-10-16
> 目的：GEPA 不是新概念，是把 ML 已懂的「进化算法 + 多目标优化」用 LLM 重组合。本表用已知框架理解新词，降认知门槛。
> 上游：`gepa_space/00_学习方案.md`（理论人话版）+ `gepa-optimization` skill（跑法+坑）。

---

## 一、GEPA 在 ML 地图上的位置（一句话定位）

**GEPA 属于「黑盒优化 / 进化计算」家族，不属于「基于梯度」也不属于「强化学习」。**

```
ML 优化方法三大族：
  ① 梯度法（SGD/Adam）         —— 要 loss 可微，走 gradient
  ② 强化学习（RL/PPO）          —— 学 state→action 策略，要海量环境交互 + reward
  ③ 黑盒优化（进化算法/贝叶斯优化/CMA-ES）
        └─ GEPA = 遗传算法(GA) + 帕累托多目标优化 + 把「变异算子」换成 LLM
```

GEPA 不需要梯度（不可微的目标函数也能优化），不学策略（不是 MDP），只需要一个「能打分的 evaluator」。这是它和 ①② 最本质的区别。

## 三、三个关键机制的精确对照

### 1. ASI = 文本版梯度（最关键，直接对标梯度下降）


|      | 梯度法                        | GEPA                                |
| ---- | -------------------------- | ----------------------------------- |
| 反馈信号 | 标量 loss + 梯度向量（知道往哪个方向调权重） | ASI 诊断信息（知道**为什么坏 + 怎么改**）          |
| 谁给信号 | 反向传播                       | evaluator 返回 error/traceback/stdout |
| 效率   | 一步到位（可微）                   | 100\~500 次评估（比 RL 快 \~35x，不可微也能用）   |


**核心**：RL 的 reward 只有标量「好/坏」，GEPA 的 ASI 是「坏在哪 + 怎么改」，等价于把梯度信息塞进了文本。

### 2. 帕累托前沿 = 多目标优化的非支配集

- 普通优化：全局平均最优，把「某子任务特别强」的候选平均掉了。
- GEPA：`{样本1: 最高分, 样本2: 最高分, ...}`，每个子任务上的冠军都保留，不互相淘汰。
- ML 对标：多目标优化里的 **Pareto front（非支配集）**——不为了一个目标牺牲另一个目标的局部最优。

### 3. 反思变异 = 把「随机变异」换成「LLM 诊断式变异」

- 传统遗传算法：变异 = 随机扰动（blind mutation），靠海量试错筛选。
- GEPA：变异 = LLM 读 ASI 诊断「为什么坏」→ 生成「改成什么样」。
- 反思和变异是**同一次 LLM 调用**完成（边读错误边吐改进），这是 GEPA 对 GA 的唯一、也是最核心的升级。

## 四、「为什么不是 RL / MDP」的精确区分


| 维度   | RL / MDP                | GEPA             |
| ---- | ----------------------- | ---------------- |
| 学什么  | state→action policy（策略） | 不学策略，学「更好的文本候选」  |
| 需要什么 | 环境 + 预标注 reward + 海量交互  | 一个能打分的 evaluator |
| 反馈   | 标量 reward               | ASI（诊断信息）        |
| 本质   | 序贯决策                    | 进化搜索             |


**直接结论**：你之前担心「决策链库缺 result 列」——GEPA 根本不需要历史 result 列。evaluator 每次评估时**现打分 + 现返回 side\_info**，这就是 reward + 梯度，运行时给，不用预标注。

---

## 五、用 ML 人已知框架的一句话总结

> GEPA = **遗传算法**（种群 + 变异 + 精英保留），把「随机变异」换成 **LLM 读错误再改**（反思变异），用 **evaluator 返回的 ASI** 当文本版梯度，用 **帕累托前沿** 做多目标非支配保留。它解决的是「**不可微、没预标注 reward、但能打分**」的优化问题——正是 prompt/代码/配置/agent 架构这类「文本参数」的处境。
