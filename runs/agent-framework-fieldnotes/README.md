# 一周实测 4 个 Agent 框架：能跑通 ≠ 跑对了

> 2026-10 的一周实测记录。成本 **$60.24 / 13.36M input tokens / 72 个会话**（含 agent 框架攻坚 44%、复盘编排 10%、基建排障 10%）。
> 本文只写**踩过的坑和可复用的判断**，不写教程（教程网上够多了，坑没人写）。
> 边界声明：单机、macOS、单周样本，不是 benchmark 排名，是"我踩完之后下次怎么选"。

---

## 三条硬结论（先给结论，后面是证据）

### 结论 1：`for 循环 + subagent 壳` ≠ 多 agent，质量差 9–20 倍

我第一版拿代码写了个 leader：读任务 → for 循环依次 `start_task` 派给子 agent → 汇总。6 个产物"齐全"，我自己判定"多 agent 跑通"。

被打回，一句话问到了本质：

> 「这个不是多个 Agent，和我写不同的 for 循环有什么区别？」

后来改成 **1 个 LLM 主 agent 自主委托**（框架原生 TaskToolSet），再跑同样 6 个产物：

| 产物 | for 循环版 | 主 agent 自主委托版 |
|---|---|---|
| 04 基础概念 | 薄，缺机制层 | 厚约 **9×** |
| 06 案例 | 罗列，无取舍 | 厚约 **20×** |
| 端到端 | 6/6 "齐全" | 6/6 且可读 |

**判据（复跑用）**：如果你能画出"第几步派给谁"的固定流程图，那就不是多 agent，是批处理。多 agent 的标志是**编排路径由模型在运行时决定**，你只能画出允许的动作空间，画不出流程图。

**成本**：这一版 6 个产物端到端 **$1.1655**（flash，input 3.39M，cache hit 77%）。"齐全"很便宜，"合格"不便宜。

### 结论 2：让 LLM 自己打分，评测器会脑补分数 —— 你跑通的是假流程

这是这周最贵的一课。我在一个 RSI（自进化）闭环里，用 LLM evaluator 给 agent 产出打分，拿到了 `baseline 54.01`，判定"benchmark + eval 两步已跑通"。

真相是：**materials 文件缺失/造假的情况下，LLM 仍然给出了 54.01 这个看起来很专业的分数**——它是脑补的，不是算的。

一句话总结：

> **评分地基是假的，跑通的是假流程。**

翻车链条：
1. 用 LLM 当裁判 → 2. 裁判在材料不全时仍然给分（大模型不会说"我算不出来"）→ 3. 分数看起来合理 → 4. 我拿这个分数判定闭环通过 → 5. 整个 RSI 闭环建在沙子上

**修法（复跑判据）**：评分必须是**确定性函数**——同样的输入永远同样的分数，且**输入缺失时必须报错而不是给分**。判断一个评测器真假，只需要一个测试：把 materials 删掉，看它是报错还是给分。给分的就是假裁判。

**推论**：任何"AI 自评 → 自我改进"的闭环，第一步都是把评分换成确定性代码；否则你优化的是裁判的想象。

### 结论 3：能跑通 ≠ 能给别人用

同一周里，有 5 个东西"在我机器上跑通了"：GEPA 无 DSPy 优化、800M 小模型决策、mem0 端到端、状态机主动编排、短剧 pipeline。

一周后能给别人复跑的是 **0 个**。

差别只有一个：**跑通 = 我的环境能跑；可分发 = 别人不需要我的环境**。后者需要 3 样东西，缺一不可：

1. 一个入口命令（不是 7 个脚本）
2. 输入样例（别人的数据长什么样）
3. 一个可判定的成功信号（不是"我看了一眼觉得对"）

没这 3 样的产出，都算**作业**，不算**作品**。作业自己交，作品才分发。

## 框架对照：4 个跑过之后的选型判断

| 框架 | 定位 | 实测结论 | 什么时候用 |
|---|---|---|---|
| **OpenHands（SDK）** | 可编程软件 agent | **唯一同时满足「Python import + 自托管 + 任意模型网关 + ACP 兼容」的 SDK 层**。`run_goal` / AgentDefinition 可直接嵌进自己的流水线 | 要把 agent 当**库**用、塞进已有 pipeline —— 主力选它 |
| **PenguinHarness** | 自进化（RSI）实验台 | 机制值得借（进化闭环、benchmark 管理），但**评分架构是错的**（用 Workspace + LLM 打分而非确定性回测）→ 借机制，别信它的分 | 想研究"生成→变异→筛"闭环，但必须自己换确定性评测 |
| **DSH（DeepSeek Harness）** | 多 profile 的 agent 运行时 | 三个实证劝退：① 包版本三代共存（0.1.x / 0.2.0-rc / 新 API 并存）② 太灵活 → 三层 patch 互相覆盖、配置面失控 ③ 生态插件滞后于运行时（插件最高 0.1.6，运行时已 0.2） | 只当交互式 client 用，**不当实验平台** |
| **Prime Agent** | 长程任务 / 决策链 | 定位是长程与决策复用，**不是轻量 coding**。本机 claude / codex / opencode 三个 CLI 开箱更快 | 长程任务编排；写代码别用它 |

**一句话选型**：**库 → OpenHands；研究自进化 → Penguin 的机制 + 自己的评测器；日常写代码 → CLI 三件套；DSH 只当壳。**

## 一周里最贵的 3 个反模式（下次直接跳过）

| 反模式 | 症状 | 代价 |
|---|---|---|
| **臆断不实测** | "这个应该不行 / 应该是网络抖动" → 结论写进文档 → 被实测推翻 | 反复改写结论 + 信任损耗 |
| **自建等价物** | 已有 vendor 里的实现不用，自己从零写一个"等价的" | 4 天里有 2 天在重写别人写好的东西 |
| **把 `unknown` 当 0** | 数据缺失时策略静默跳过 = 假绿 | 整个评测结论失效（见结论 2） |

## 可复跑的最小验证（给要抄的人）

想验证"你的 agent 是真多 agent 还是 for 循环套壳"，三步：

1. **画流程图**：能画出固定派发顺序 → 是批处理，不是多 agent。
2. **删输入测裁判**：把评测依赖的文件删掉，跑一次。报错 = 真裁判；给分 = 假裁判。
3. **换环境跑**：把产物拷到干净机器，只给一个入口命令。跑不起来 = 未完成分发。
